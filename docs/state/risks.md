# Risk Register

> Status: Phase 0 · Last updated: 2026-11-26 · Likelihood/impact are qualitative judgments (L/M/H), not measurements

| ID | Risk | Category | Likelihood | Impact | Mitigation | Trigger to revisit |
|----|------|----------|-----------|--------|------------|--------------------|
| RK-01 | **OS-level gains are negligible for GPU-resident inference** (H-L-01, H-S-02, H-D-03); the kernel/system layer adds little over runtime flags | Strategy | M–H | H | Measure first (Phase 1, arms U0/U1/U2/A); focus OS work where evidence suggests effects: CPU/MoE offload, model loading, concurrency/tail latency, energy (H-K-01, H-K-02, H-S-01, H-S-06); keep layer mode as product if confirmed (ADR-0005) | Phase 1 baseline results |
| RK-02 | **False improvements from measurement noise** lead to wrong defaults or claims | Method | H (without countermeasures) | H | RMIT, A/A calibration, multi-level repetition, winner re-validation, effect-size CIs [S-10][S-47][S-50]; harness self-validation (`benchmarking.md` §8) | A/A false-positive rate above target |
| RK-03 | **Silent quality regressions** from engine/kernel updates or "lossless" knobs (e.g. FP8 attention bug [R-07]) | Quality | M | H | Quality gate on every bundle update and every candidate; lossy knobs opt-in only (ADR-0004) | Any gate failure in canary suite |
| RK-04 | **Upstream churn** (ROCm 7.14→10.0 jump [R-33], IPEX/IPEX-LLM archived [L-27][L-28], TGI maintenance mode [R-08], LLMPerf archived [S-60]) breaks integrations | Ecosystem | H | M | Depend on upstream-mainstream paths; pin bundles; provider/bundle abstraction (ADR-0007); re-validation on version change (ADR-0010) | Major upstream release |
| RK-05 | **Proprietary stack constraints**: CUDA/cuDNN/TensorRT redistribution limits, NVIDIA userspace/firmware version coupling, Secure Boot signing [D-59][D-61] | Legal/technical | H | M | Fetch on demand; CI-signed open modules; legal review; open fallback paths (CPU/Vulkan) | Legal review outcome; E-04 result |
| RK-06 | **Maintenance overload** of an own image for a small team (cf. Clear Linux ending [L-26]) | Organization | M–H | H | Layer-first (ADR-0005); upstream-first; small host matrix; shadow-derivative experiment E-06 before committing | E-06 effort exceeds capacity |
| RK-07 | **Privileged tuning daemon becomes an attack surface** (TuneD had local privilege CVEs [S-01]) | Security | M | H | Minimal privileged `ailxd`, narrow IPC, polkit, no shell execution, allow-listed knobs only, fuzzing and review | Any security report |
| RK-08 | **Agents executing generated code** increase exposure; pressure to drop mitigations for speed | Security | M | H | Mitigations stay on (forbidden list in [K-*] security table); sandboxing designed with performance measured, not assumed | — |
| RK-09 | **Single-hardware bias**: early defaults tuned on one RTX 4090 / 7950X3D generalize poorly | Validity | H | M | Profiles keyed by hardware profile; community validation network; acquire AMD/Intel test hardware in Phase 4 | First non-NVIDIA tests |
| RK-10 | **GPU sharing on consumer GPUs is fragile** (no MIG, MPS on GeForce unclear and weakens isolation [R-41][R-42]) | Technical | H | M | Time-slicing + VRAM broker via engine sleep/unload hooks (O-R-06); research arbitration (XSched) opt-in only | OOM/latency results of W-MIX-1 |
| RK-11 | **Hardware damage/instability** from power/clock tuning | Safety | L | H | Optimizer may only lower power limits within vendor range; over-clock/over-volt never auto-proposed; thermal guard metrics | Throttling or error events |
| RK-12 | **Privacy leakage** via shared results/fingerprints | Privacy | M | M | Opt-in only; fingerprint coarsening; local-first default (ADR-0004) | Before first public results DB |
| RK-13 | **Legal obligations** (EU CRA steward duties, licence set, trademark) misjudged [D-89][D-90][D-91] | Legal | M | M | Legal review before code release; SBOM/SLSA/CVD from day one | Legal review; Dec 2027 CRA milestone |
| RK-14 | **Benchmark overfitting** (Goodhart): tuning for the suite, not for users | Validity | M | M | Held-out workloads; opt-in local trace capture; periodic suite refresh | Divergence between suite and user-trace results |
| RK-15 | **Scope creep** across all workload classes at once | Organization | H | M | MVP scope: LLM inference + model loading + one image workload + concurrency; video/training later (`roadmap.md`) | Roadmap reviews |
| RK-16 | **New kernel defaults regress silently** (e.g. `SCHED_CACHE` since 7.2 on multi-CCD CPUs, H-K-01 [K-19][K-20]) | Technical | M | M | Baseline canary across kernel updates; change-point detection; upstream reports | Kernel update in baseline |
| RK-17 | **Phase 0 evidence gaps**: some facts seen only as search snippets or from prior knowledge ("PK"), due to sandbox network limits (`research/00-method.md`) | Method | M | M | Phase 1 task: verify all PK/snippet-only facts that feed ADRs; keep ADRs "Proposed" until then | Phase 1 start |
| RK-18 | **Vendor capture** of governance or roadmap | Governance | L–M | H | Vendor-neutral governance roadmap; no single-organization majority (`community-and-licensing.md`) | Steering-council formation |
